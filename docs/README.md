# Documentation

This index separates practical guides, API references, asset specifications, and development workflows. The repository root [README](../README.md) is the project overview; it is not intended to be a changelog or a complete API reference.

## Start here

- [Getting started](guides/getting-started.md) — install the engine, create a stage, and run a small game loop.
- [Stage and rendering](reference/stage.md) — renderer selection, stage setup, lighting, camera, and frame loop.
- [Physics](reference/physics.md) — worlds, collision geometry, balls, and simulation steps.
- [Input](reference/input.md) — keyboard, pointer, touch, gamepad, and custom actions.
- [Graphics API](reference/gfx.md) — the engine's scene, geometry, material, and math layer.
- [Module map](reference/modules.md) — import paths and the main public entry points.

## Guides and API reference

The guides explain how the systems fit together. The reference pages describe the current interfaces and their options.

- [People and characters](people.md) — human and robot models, clothing, customization, animation, fighting, and object handling.
- [Weapons](weapons.md) — weapon categories, dimensions, variants, and construction options.
- [Venue kit](venue.md) — tile-based rolling-game venues and their simulation and rendering modules.

## Assets and materials

- [Generated library catalog](library.md) — shared-library characters, props, heroes, scenery, textures, and music, including engine-authored entries. This is generated by `npm run extract`; do not edit it by hand.
- [Granite kitchen](granite-kitchen.md) — counter, sink, dimensions, and material options.
- [Wood textures](wood.md) — source photographs, sampling notes, and attribution requirements.

## Development workflows

- [Adding the engine to an existing game](dropping-in.md) — migration approach, current game status, and compatibility verification.
- [Asset ideas backlog](development/asset-backlog.md) — an internal planning list, not a catalog of assets already in the engine.

## Keeping the documentation accurate

The source code and package export map are authoritative. When an API changes, update its reference page and examples in the same change. Keep generated pages generated, and avoid copying full API descriptions into the root README.
